# Public Schema and Studio Parity

Status: Phase 1 contract, 2026-08-10. Runtime API `1`; workspace schema `1`.

Every stable V1 property is either directly editable in Studio, explicitly read-only, or designated agent/API-only with a product reason. The **Canonical details · read-only** section exposes the exact selected-node representation, including full IDs and advanced values, so agent-created state is never invisible merely because a dedicated control is absent.

## No-normalization rule

Opening Studio or Canonical details performs no mutation. Read-only properties are serialized for display only. A value changes only through an explicit transaction, including legacy clipping normalization. This protects agent-created advanced state from default-control coercion.

## Promotion rule

An agent/API-only item may become directly editable only with validation, accessible controls, preview/commit behavior proportional to risk, history/recovery coverage, and proof that unrelated node IDs and properties remain unchanged.
